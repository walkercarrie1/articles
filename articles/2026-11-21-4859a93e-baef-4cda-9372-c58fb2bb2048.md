# 用唯一索引兜住消息表的重复写入

<!-- content-workspace-job:4859a93e-baef-4cda-9372-c58fb2bb2048 -->

## 问题场景

消息表的写入先查后插，两个并发请求同时查到不存在，于是各插了一条。业务侧统计翻倍，清理时又不敢确定哪条该留。

## 实现步骤

在业务唯一键上建唯一索引，让数据库来保证不重复。

```sql
ALTER TABLE messages ADD UNIQUE KEY uk_size (size);
```

写入改成先尝试插入，冲突时按业务决定忽略还是更新。

```sql
INSERT INTO messages (id, size) VALUES (1, 1024)
ON DUPLICATE KEY UPDATE size = VALUES(size);
```

确认索引真的生效，冲突时应当报 1062 而不是静默成功。

```sql
SELECT COUNT(*) FROM messages WHERE size = 100;
SHOW INDEX FROM messages WHERE Key_name = 'uk_size';
```
