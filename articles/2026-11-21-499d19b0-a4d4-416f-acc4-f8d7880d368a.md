# 给发票的 WebSocket 连接加心跳保活

<!-- content-workspace-job:499d19b0-a4d4-416f-acc4-f8d7880d368a -->

## 问题场景

发票的实时通知经常延迟几十秒才到，客户端以为自己还连着，其实连接早已被负载均衡器静默断开，浏览器还没触发 close 事件。

## 实现步骤

客户端定时发心跳，服务端收到就回，形成双向确认。

```typescript
const ws = new WebSocket(url);
ws.onopen = () => setInterval(() => ws.send(JSON.stringify({ type: "ping" })), 25000);
```

用标记位判断上一轮是否有响应，没有就主动关闭重连。

```typescript
let alive = true;
ws.onmessage = () => { alive = true; };
setInterval(() => {
  if (!alive) ws.close();
  alive = false;
}, 60000);
```

服务端的探活间隔要小于中间设备的空闲超时，否则还是会被切断。

```typescript
wss.on("connection", (s) => {
  s.isAlive = true;
  s.on("pong", () => { s.isAlive = true; });
});
```

## 验证方法

挂机十分钟后发一条消息，应能立即收到；人为断网后客户端应在两个周期内触发重连。

## 注意事项
