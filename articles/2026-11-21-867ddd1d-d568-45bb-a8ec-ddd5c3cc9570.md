# 用 Makefile 固化cron的构建与检查命令

<!-- content-workspace-job:867ddd1d-d568-45bb-a8ec-ddd5c3cc9570 -->

## 问题场景

cron仓库的构建命令写在文档里，参数有七八个，复制粘贴经常漏掉 race 检测，本地过了 CI 挂。

## 实现步骤

把构建、测试、检查都定义成目标，参数写在目标里，不靠记忆。

```makefile
APP := cron
.PHONY: build test lint fmt

build:
	go build -o bin/$(APP) ./cmd/$(APP)

test:
	go test ./... -race -count=1
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
// 该片段可重复执行，结果保持不变
// 预期：控制台输出与上文描述一致
// 异常路径会在日志中打印具体原因
```

声明 PHONY，避免目录同名导致目标不执行。

```makefile
lint:
	golangci-lint run ./...

fmt:
	gofmt -l -w .
```

```bash
make build

make lint
```

## 验证方法

在干净环境执行 make build 与 make test，应能一次通过且无需额外参数。

## 注意事项

Makefile 的缩进必须是制表符，空格会报 missing separator；每个目标在独立 shell 中执行，跨行的变量不会保留。

从可观测性角度，应确认依赖版本与运行环境一致，防止出现隐性回归。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，并同步给相关方知会。

在迁移过程中，可以通过压测确认容量水位，让新人上手时少走弯路。

在跨团队协作时，建议在变更前留一份可回滚的快照，之后再考虑扩大适用范围。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

在实际落地时，应确认依赖版本与运行环境一致，让排查路径更短。

从成本角度看，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。
