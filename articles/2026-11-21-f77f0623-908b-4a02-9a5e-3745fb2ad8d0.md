# 为事件表的payload统计建覆盖索引消除回表

<!-- content-workspace-job:f77f0623-908b-4a02-9a5e-3745fb2ad8d0 -->

## 问题场景

事件表的汇总查询只用到payload一列，却每次都回表几百万次，磁盘读放大严重，统计接口常年占着数据库三成负载。

## 实现步骤

确认查询涉及的列，全部放进联合索引，形成覆盖。

```sql
SELECT payload, COUNT(*) FROM events GROUP BY payload;
```

索引列顺序按等值在前、范围在后排列，最左前缀才用得上。

```sql
CREATE INDEX idx_payload ON events (payload, id);
```

用 EXPLAIN 的 Extra 列确认出现 Using index，说明没有回表。

```sql
EXPLAIN SELECT payload FROM events WHERE payload > 4096;
```

## 注意事项

覆盖索引会让索引变大，写入成本上升，更新频繁的表要权衡；SELECT * 一定会回表，统计查询应显式列出需要的列。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，确保线上行为始终可控。

在多人协作的项目里，应当拆分步骤以便中途校验，并保留回滚开关以便快速恢复。

在压测阶段，应把关键参数集中到配置中心统一管理，使运维成本保持在合理区间。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。
