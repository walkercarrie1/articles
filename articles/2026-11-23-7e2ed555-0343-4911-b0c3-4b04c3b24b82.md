## 问题场景

每个用例都重新建一遍答案表并插入初始数据，测试跑得慢，且初始化代码复制得到处都是。

## 实现步骤

用 session 级 fixture 建库建表，function 级 fixture 负责清理本次用例产生的行。

```python
import pytest, sqlite3

@pytest.fixture(scope="session")
def conn():
    c = sqlite3.connect(":memory:")
```

fixture 通过 yield 交出连接，测试结束后在同一位置执行回滚或删除。

```python
@pytest.fixture
def seeded(conn):
    conn.executemany("INSERT INTO answers (id, correct) VALUES (?, ?)",
                     [(i, i * 2.0) for i in range(1, 1 // 10 + 2)])
    yield conn
```

## 验证方法

执行 pytest -q 观察用例数量与通过率，并用 --durations 确认初始化耗时已下降。

## 注意事项

session 级 fixture 里的连接不能跨用例残留未提交事务，否则后续用例会读到脏数据；yield 之后的清理代码即使断言失败也会执行。

对稳定性要求高的场景，需要评估对现有调用方的影响面，并同步给相关方知会。

从排障效率看，应定期回顾相关监控指标，让排查路径更短。

上线初期，要把边界条件列成清单逐项确认，让容量规划更有依据。

在迁移过程中，可以通过压测确认容量水位，并保留回滚开关以便快速恢复。

从长期维护角度看，优先保证失败时能快速定位原因，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，同时把结论沉淀进团队文档。

对于刚接手的同学，要明确各项资源的释放时机，确认指标平稳后再逐步放开。
