# 试卷主题切换只改 CSS 变量不动结构

<!-- content-workspace-job:3e4a92ea-3728-4377-ae70-1fff7bb46a30 -->

## 问题场景

试卷后台要支持深浅两套主题，原先每个组件都写死了颜色，改一次要动几十个文件。

## 实现步骤

在根选择器上定义颜色变量，组件样式一律引用变量而不是字面值。

```css
:root {
  --bg: #ffffff;
  --fg: #1f2328;
  --line: #d8dee4;
}
:root[data-theme="dark"] {
  --bg: #16181d;
  --fg: #e6edf3;
  --line: #30363d;
}
```

切换主题时只改根节点的类名，由类名覆盖变量取值。

```javascript
.card {
  background: var(--bg);
  color: var(--fg);
  border: 1px solid var(--line);
  padding: 12px 16px;
}
```

把选择结果写入本地存储，刷新后先读回再渲染，避免闪白。

```javascript
const root = document.documentElement;
function apply(mode) {
  root.dataset.theme = mode;
  localStorage.setItem('paper-theme', mode);
}
```

## 注意事项

变量要定义在包含所有组件的作用域上，写在组件内部无法被全局覆盖；内联样式优先级更高，会盖掉变量。

在多人协作的项目里，应当限定作用范围避免影响其他业务，使整体改动风险可控。

考虑到线上环境的差异，需要同时关注错误率与延迟两个指标，便于横向对比不同方案的效果。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，并同步给相关方知会。

在迁移过程中，可以通过压测确认容量水位，让新人上手时少走弯路。

在跨团队协作时，建议在变更前留一份可回滚的快照，之后再考虑扩大适用范围。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

从长期维护角度看，优先保证失败时能快速定位原因，减少不必要的返工成本。

遇到复杂链路时，优先保证失败时能快速定位原因，并同步给相关方知会。

结合团队现状，可以通过日志补充上下文信息，避免问题积累到难以收场。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，并保留回滚开关以便快速恢复。
