# 视频配置用 dataclass 做入参校验

## 问题场景

视频模块从字典读配置，键名拼错或类型不对时要等运行到深处才报错，排查成本很高。

## 实现步骤

用 dataclass 声明字段与默认值，在 __post_init__ 里做范围校验。

```python
from dataclasses import dataclass, field

@dataclass
class Config:
    name: str = "video"
    limit: int = 900
    tags: list = field(default_factory=list)

    def __post_init__(self):
        if not 1 <= self.limit <= 100000:
            raise ValueError("limit 越界: %s" % self.limit)
```

从环境变量或文件读出原始字典后统一转换，非法值直接抛错并带上字段名。

```python
def parse(raw):
    return Config(name=raw.get("name", "video"),
                  limit=int(raw.get("limit", 900)),
                  tags=list(raw.get("tags", [])))
```

## 验证方法

分别传入合法值与越界值，合法值应正常构造，越界值应抛出带字段名的异常。

## 注意事项

dataclass 默认不做类型检查，注释只是注释；可变默认值要用 field(default_factory=...)，直接写列表会共享同一个对象。

从成本角度看，应当拆分步骤以便中途校验，让新人上手时少走弯路。

从长期维护角度看，先把最小可复现的用例固定下来，让容量规划更有依据。

经过几轮迭代后，需要同时关注错误率与延迟两个指标，并保留回滚开关以便快速恢复。

上线初期，要把异常路径和正常路径分别覆盖一遍，减少不必要的返工成本。

在压测阶段，应把关键参数集中到配置中心统一管理，同时把结论沉淀进团队文档。

在资源受限的环境下，建议在变更前留一份可回滚的快照，让新人上手时少走弯路。

在跨团队协作时，建议在变更前留一份可回滚的快照，让新人上手时少走弯路。

遇到复杂链路时，优先保证失败时能快速定位原因，确保线上行为始终可控。

考虑到线上环境的差异，建议先在预发环境跑一轮完整流程，使整体改动风险可控。

在迁移过程中，可以通过压测确认容量水位，便于横向对比不同方案的效果。

从长期维护角度看，优先保证失败时能快速定位原因，并同步给相关方知会。

经过几轮迭代后，建议先在预发环境跑一轮完整流程，保证每一步都可验证。
