# 集群推送用 SSE 并在断线后自动重连

<!-- content-workspace-job:5f35940b-2b4d-454f-8956-dbca3ae5c708 -->

## 问题场景

集群状态需要近实时更新，轮询开销大且延迟高，直接用长连接又容易在弱网下静默断开。

## 实现步骤

用 EventSource 订阅推送地址，监听 message 事件更新状态。

```javascript
function connect(url, onData) {
  let delay = 1000;
  const open = () => {
    const es = new EventSource(url);
    es.onmessage = (e) => { delay = 1000; onData(JSON.parse(e.data)); };
    es.onerror = () => { es.close(); setTimeout(open, delay); delay = Math.min(delay * 2, 30000); };
    return es;
  };
  return open();
}
```

监听 error，在连接关闭后按递增间隔重建，避免密集重试。

```javascript
const state = { count: 0 };
const es = connect('/api/cluster/stream', (msg) => {
  state.count += 1;
  document.querySelector('#cluster-badge').textContent = state.count;
});
```

## 注意事项

EventSource 只支持 GET，鉴权要放在 cookie 或查询参数；浏览器对同域并发连接数有限制，多标签页会互相挤占。

在多人协作的项目里，应当限定作用范围避免影响其他业务，使整体改动风险可控。

考虑到线上环境的差异，需要同时关注错误率与延迟两个指标，便于横向对比不同方案的效果。

结合历史事故记录，要把异常路径和正常路径分别覆盖一遍，并同步给相关方知会。

在迁移过程中，可以通过压测确认容量水位，让新人上手时少走弯路。

在跨团队协作时，建议在变更前留一份可回滚的快照，之后再考虑扩大适用范围。

从可观测性角度，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。
