# 薪资页面弹层关闭后把焦点还给触发按钮

<!-- content-workspace-job:42d1e688-03c8-4ab5-9429-f1b0cd7d401b -->

## 问题场景

薪资弹层关闭后焦点回到页面顶部，键盘操作者需要重新 Tab 十几次才能回到原来的位置。

## 实现步骤

打开弹层前记录 document.activeElement 作为返回目标。

```javascript
let lastFocus = null;
function openDialog(dlg) {
  lastFocus = document.activeElement;
  dlg.hidden = false;
  const first = dlg.querySelector('button, [href], input');
  if (first) first.focus();
}
```

弹层内做焦点循环，Tab 到末尾时回到第一个可聚焦元素。

```javascript
function closeDialog(dlg) {
  dlg.hidden = true;
  if (lastFocus && document.contains(lastFocus)) lastFocus.focus();
  lastFocus = null;
}
```

## 验证方法

用键盘打开再关闭弹层，焦点应回到触发按钮，连续按 Tab 不应跳出弹层。

## 注意事项

display:none 的元素不可聚焦，恢复焦点前要确保元素仍可见；aria-modal 需要配合实际焦点限制才有效。

在实际落地时，建议先在小流量环境验证行为是否符合预期，以便快速定位瓶颈。

从成本角度看，应当拆分步骤以便中途校验，便于横向对比不同方案的效果。

如果数据量继续增长，需要评估对现有调用方的影响面，并同步给相关方知会。

对稳定性要求高的场景，需要评估对现有调用方的影响面，确认指标平稳后再逐步放开。

上线初期，要把异常路径和正常路径分别覆盖一遍，确保线上行为始终可控。

在实际落地时，应确认依赖版本与运行环境一致，降低同类问题再次发生的概率。

在资源受限的环境下，建议在变更前留一份可回滚的快照，并保留回滚开关以便快速恢复。

如果数据量继续增长，优先用工具把现状量化出来再动手，防止出现隐性回归。

对稳定性要求高的场景，优先用工具把现状量化出来再动手，以便后续复盘有据可查。

从可观测性角度，建议先在小流量环境验证行为是否符合预期，确认指标平稳后再逐步放开。
